# field-library: Sidebar with Text and Images sections
Scope: area:sidebar

## Goal
Provide the sidebar that lists every element the user can place on the document: a `Text` section
with a free `Text` element for document-specific values that are not saved, the `Today's date` value,
and user-defined saved text values, plus an `Images` section for saved images such as signatures.
Placement and editing on the page are defined by `pdf-viewer`.

## Requirements
- R1: The sidebar has two sections in this order: `Text` and `Images`. `Text` lists, in order: one free `Text` item (creates an empty text element and is never persisted), the `Today's date` item (R7), then saved text items (R2). `Images` lists saved image items (R3). The sidebar is always visible so values can be managed without a document. Until a PDF is loaded, placement is disabled with tooltip `Open a PDF to place fields`. On desktop, every item's `Move` handle is dragged onto the PDF to place it (R15); `Place` places any item on any width.
- R2: The `Text` section heading has an `Add text` button opening a dialog with `Label` (required, 1–100 chars) and `Value` (required, multi-line); `Save` appends it to the end of the saved text items and persists it. A saved text item displays only a truncated preview of its value, not its label. Example: label `Tax code`, value `RSSMRA80A01H501U` shows `RSSMRA80A01H501U`.
- R3: The `Images` section heading has an `Add image` button opening a dialog with `Label` (required, 1–100 chars) and a file picker accepting PNG and JPEG only; the item shows a thumbnail at the start of the preview column, aligned with the text labels (R12). Other formats (checked by content, not just extension) are rejected with `Only PNG and JPEG images are supported.` PNG transparency is preserved. No app-level size limit.
- R4: Every saved item has icon-only `Move`, `Place`, `Edit` and `Delete` controls with accessible names and tooltips, in the slots defined by R12. `Edit` changes the label/value, or label/replaces the image. `Delete` asks `Delete "<label>"?` with `Cancel`/`Delete`, and removes the stored image file for image items.
- R5: Saved items are reordered within their section by dragging their `Move` handle; the full order persists across reloads, and items of the other section keep their positions. Dropping the handle on the PDF places the item instead (R15).
- R6: Saved values and images persist on the server in `DATA_DIR` and survive server restarts. All browsers reaching the server share the same data (last write wins).
- R7: Settings are server-side. The `Today's date` item in the `Text` section shows only its formatted-date value, with no label, and its format button cycles through `dd/MM/yyyy` (default), `MM/dd/yyyy`, `yyyy-MM-dd`, `dd.MM.yyyy`, then wraps to the first format. The selected format persists. `Today's date` uses the browser's local date at placement time, e.g. 12 Nov 2026 with `dd/MM/yyyy` → `12/11/2026`.
- R8: Placing any sidebar item creates an independent element: later edits on the page do not change the saved value, and editing/deleting a saved value does not change already placed elements.
- R9: If the API is unreachable or fails, the `Text` and `Images` sections show `Could not load saved values.` with `Retry`, and failed saves show an error snackbar keeping dialog input. The free `Text` item and `Today's date` (using the default format if settings failed) remain usable; PDF viewing and export are unaffected.
- R10: Below `768px`, the sidebar is a bottom sheet opened by a `Fields` button; tapping `Place` on any item, including the free `Text` item, places it (per `pdf-viewer`) and closes the sheet. Management actions (add/edit/delete/reorder) remain available in the sheet.
- R11: REST API (`/api`), JSON unless noted, validated server-side with 400 on invalid input, 404 on unknown IDs, 415 on unsupported image type:
  `GET /values`; `POST /values` (text); `POST /values/image` (multipart `label`, `file`); `PUT /values/:id` (label/text); `PUT /values/:id/image` (multipart replace); `DELETE /values/:id`; `PUT /values/order` (`{ ids }`, must be a permutation of existing IDs); `GET /images/:id` (bytes with correct `Content-Type`); `GET /settings`; `PUT /settings` (`{ dateFormat }`, one of the four presets). IDs are server-generated UUIDs; any non-UUID ID is rejected (no path traversal).
- R12: All item rows (free `Text`, `Today's date`, saved text, saved image) share one layout: fixed 48px height and 8px radius. Left to right: a 40px `Move` slot holding the drag handle of every item, an empty 32px spacer slot, a flexible preview column in which text and image thumbnails start at the same x in every row, unindented and left-aligned, then 40px action slots in the order `Place`, `Edit`, `Delete`. Actions that do not apply leave their slot empty, so icons align in every row. All icons are 18px. `Today's date` uses its `Edit` slot for the date-format button and leaves `Delete` empty.
- R13: Row icons render unclipped: each icon's SVG is `18x18px`, fills its `18px` icon box and is centered in its 40px action slot. `Place` uses a plus inside a square that adds the item to the document, not a map pin.
- R14: The `Today's date` format button shows a switch glyph with two arrows, one pointing right above one pointing left. It stays icon-only in its `Edit` slot with accessible name and tooltip `Change date format`.
- R15: On desktop, dragging an item's `Move` handle onto a page places that item at the drop point and selects it, as `pdf-viewer` R6 specifies: the free `Text` (empty, in edit mode), `Today's date` (its date text), a saved text (its text) and a saved image (its image). Dropping outside every page places nothing. Below `768px` the item is placed with `Place` (R10).
