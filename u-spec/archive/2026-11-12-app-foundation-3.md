## Goal
Bootstrap SelfSign, a self-hosted web app that visually signs and fills PDFs entirely in the browser.
Define the project-wide stack, Docker deployment, privacy rules, theme, layout and bundled fonts
shared by the `viewer`, `sidebar` and `export` areas. The shared UI uses rounded controls,
floating tool surfaces, a right-side desktop Fields panel and vertically centered theme icons.
Use the supplied SelfSign symbol beside a smaller theme-aware logotype in the header, derive
production favicon assets from the supplied symbol, and provide a mobile Fields FAB that moves
with the bottom sheet and becomes its close control while open.
Cryptographic/digital signatures (PAdES, certificates) and authentication are out of scope.
This change does not implement pending area features or PWA/offline/installability behavior.

## Requirements
- R1: The repository is an npm workspaces monorepo with `apps/web` (Angular, latest stable, standalone components, signals), `apps/server` (Node Active LTS + Fastify) and `packages/shared` (shared TypeScript types); TypeScript `strict` everywhere. Root scripts `npm run dev`, `npm run build`, `npm run lint`, `npm test`, `npm run e2e` exist and succeed on a clean checkout after `npm ci`. Framework/runtime versions are pinned.
- R2: One server process serves the Angular build as static files (SPA fallback to `index.html` for non-`/api` GET routes) and the REST API under `/api`, on `PORT` (default `8080`). Data lives in `DATA_DIR` (default `/data` in the container, `./data` in dev), created on startup if missing. `GET /api/health` returns `200 {"status":"ok"}`.
- R3: A multi-stage `Dockerfile` produces a single image that runs as a non-root user, exposes `8080`, declares volume `/data`, has a `HEALTHCHECK` on `/api/health`, and builds for `linux/amd64` and `linux/arm64`. A `docker-compose.yml` example maps `8080:8080` and a `./data:/data` volume; saved data survives `docker compose down && docker compose up -d`.
- R4: PDF processing is client-side only: PDF bytes are never sent to the server (no request body contains the PDF while loading, editing or exporting). The app makes no requests to external origins (fonts, pdf.js worker and assets are bundled). The server sends `Content-Security-Policy` restricted to `'self'` (plus `blob:`/`data:` where required for images and workers) and `X-Content-Type-Options: nosniff`.
- R5: All UI text (labels, buttons, messages, errors, tooltips, page title) is in English.
- R6: A header theme control offers `System`, `Light`, `Dark`; default `System` follows `prefers-color-scheme` and reacts live to OS changes. The choice is stored in `localStorage` and restored on reload. Both themes meet WCAG AA text contrast.
- R7: UI uses Angular Material (M3) with a custom minimal theme. Layout is desktop-first: header, document area on the left filling the available space, Fields sidebar on the right. At widths of `768px` and above the panel occupies its own layout column without covering the document. Below `768px` width the layout switches to mobile mode (sidebar as bottom sheet, defined by `field-library`) with no horizontal page scroll at 360px width except inside the zoomed document area.
- R8: Fonts `Noto Sans` (default), `Noto Serif` and `Caveat` (all OFL) are bundled locally, used both for on-screen rendering of text elements and for export, and support Latin characters including `àèéìòùÀÈÉÌÒÙ`.
- R9: `README.md` documents: purpose, privacy model (files never leave the browser), `docker compose` quick start, env vars (`PORT`, `DATA_DIR`), volume permissions for the non-root user, multi-arch build via `docker buildx build --platform linux/amd64,linux/arm64`, local development, and a security note that there is no authentication so anyone reaching the port can read/modify saved data (including signature images) and the service should be kept on a trusted network or behind a reverse proxy/VPN with auth.
- R10: Test tooling: Vitest for `apps/web`, `apps/server` and `packages/shared`; Playwright for E2E against the built server. Each area spec adds its own tests.
- R11: Theme and other segmented selection controls use one pill-shaped group with a rounded selected segment, no hard rectangular segment dividers, and a clearly distinguishable selection in light and dark themes. The theme control remains icon-only with English tooltips and accessible names `System`, `Light`, `Dark`; exactly one option is selected. Keyboard operation, visible focus, hover feedback and theme persistence remain functional.
- R12: The desktop Fields panel is an inset floating surface with all four corners rounded, a subtle elevation shadow, and visible gaps from the header, document area and window edges; it has no full-height divider attaching it to the document. Panel content scrolls within the available height without clipping its controls. At `1440x900` it appears to the right of, and does not overlap, the document area. The mobile sheet retains its existing opening, dismissal and responsive transition behavior.
- R13: Rounded controls and floating tool surfaces are shared visual rules, not one-off theme-toggle styling. Buttons and segmented controls use rounded or pill shapes; tool panels use consistent rounded corners, spacing and restrained elevation in both themes. The mobile bottom sheet has rounded top corners while remaining bottom-attached. Do not wrap every page section in a card or add nested decorative cards. Actual PDF page geometry and exported document content remain rectangular and unaffected; stack, colors, fonts and feature behavior are otherwise unchanged.
- R14: Each `System`, `Light`, `Dark` icon is vertically centered inside its actual theme button, with at most `1px` difference between their bounding-box vertical centers. Theme buttons retain a stable `36px` height and `40px` segment width; SVGs remain `18x18px`. Centering holds at `1440x900` and `360x740`, in light and dark themes, for selected and unselected options and during hover or keyboard focus. Preserve the existing icons, pill appearance, horizontal placement and theme behavior.
- R15: Copy and prepare `selfsign_logotype_light.svg`, `selfsign_logotype_dark.svg` and `selfsign_logo.svg` from the user's Downloads directory into the repository's public assets; runtime and builds must not depend on Downloads. On desktop and mobile, the header brand consists of the supplied symbol at `32x32px` on the left, an `8px` gap and the full logotype in a `100x35px` reserved box on the right, with original artwork aspect ratios preserved. The symbol and logotype bounding-box vertical centers differ by at most `1px`; no separate text label or clipped artwork is added. Use the dark-stroke `selfsign_logotype_light.svg` in the effective light theme and the light-stroke `selfsign_logotype_dark.svg` in the effective dark theme. The correct variant is shown on first render, explicit theme changes, reload and live OS changes under `System`, including when the app preference differs from the OS. Preserve artwork and colors; trim surplus empty canvas only without clipping painted content. The logotype is the single accessible brand image named `SelfSign`; the adjacent symbol is decorative and does not duplicate that name. Keep the whole brand group and theme control unclipped and non-overlapping at 360px width.
- R16: Use the supplied `selfsign_logo.svg` symbol, not the logotype, for a self-hosted favicon set: scalable square `favicon.svg` with a valid viewBox, multi-resolution `favicon.ico` containing 16px, 32px and 48px images, PNG icons at 16px and 32px, and `apple-touch-icon.png` at 180px. Generate raster outputs from the vector source rather than enlarging a small bitmap; preserve the supplied blue background, light symbol and complete artwork. Declare the appropriate local icon links, MIME types and sizes in the HTML head. Icons render nonblank and remain recognizable at 16px/32px; Apple artwork stays inside its canvas. The same favicon artwork works in both browser themes; only the header logotype changes with the app theme. Generated assets are stored in the repository and served in production/Docker without external requests. No web manifest or PWA work is required.
- R17: Below `768px`, replace the header Fields text button with one visible circular Angular Material FAB, with a stable `56x56px` touch target, local SVG icons and no visible text. Closed state: show the fields/list icon with English accessible name and tooltip `Fields`, positioned bottom right with `16px` edge spacing plus relevant safe-area insets. Activating it opens the existing Fields bottom sheet without hiding the FAB: it moves upward in sync with the sheet, stays on the same right-hand alignment, and becomes an X with accessible name and tooltip `Close Fields`. Open state: the FAB's bottom edge sits `16px` above the sheet's top edge; it remains visible above the backdrop, pointer-interactive and reachable within the dialog's keyboard focus region. Activating the X closes the sheet; it then travels down with the sheet and returns to the fields/list icon and closed position. Support Escape and backdrop dismissal, prevent duplicate sheets, and restore focus to the closed-state Fields FAB after dismissal. Keep state, accessible names and aria-expanded/aria-controls consistent with the actual dialog. Movement remains attached to the sheet during content-height changes, viewport resizing and opening/closing; respect reduced-motion preferences without losing state or position. Constrain sheet height and scroll content internally when needed so the open FAB remains inside the usable viewport below the header and safe areas. There is only one visible/interactable FAB throughout, no header Fields button and no page overflow. At `768px` and above dismiss the sheet, remove the FAB and retain the right-side Fields panel. Do not implement new field-management behavior.

## Approach
Prepared assets remain in `apps/web/public/branding/`, with the validated cropped logotype
viewBox `21 66 561 195` and `300x300` symbol. The completed favicon set and Downloads originals
are unchanged. `app.html` and `app.scss` compose the 32px decorative symbol, 8px gap and
100x35px logotype box using flex centering and preserved image aspect ratios. Existing root
theme selectors and early theme initialization continue to choose the effective logotype variant.
`apps/web/src/app/sidebar/fields-sheet.ts` is a small local wrapper around the existing Sidebar.
Its close FAB sits 16px above the content and shares the Material container's transform, so
motion and content-height changes need no position polling or private library fields. The open
control belongs to the dialog focus region above the backdrop. The closed app-root trigger is
inactive while this overlay control is present, leaving exactly one visible/interactable FAB.
The wrapper owns internal scrolling and a dynamic-viewport max-height that reserves room for
the header, FAB, gaps and safe area. Scoped global styles keep the sheet container unclipped;
reduced-motion media styles shorten movement to 1ms. Local Material list/close SVGs provide the
two states, with controls linked to the actual dialog ID. A host Escape handler dismisses the
sheet before an active tooltip can consume Escape. Existing duplicate-open guards, desktop
dismissal and native-element focus restoration are preserved.
Existing unit/E2E files now verify composed branding and the visible moving X. Geometry is
sampled atomically within a browser frame, including throughout opening/closing. The icon-size
test establishes its initial focus explicitly before checking ArrowRight navigation; the
separate selector test retains Tab/Shift+Tab and visible keyboard-focus checks.
